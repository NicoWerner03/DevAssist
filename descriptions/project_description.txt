Arbeitsablauf: Ich werde dir jetzt den Ablauf erklären wie das Tool ablaufen soll. Auf GitLab wird ein Ticket/Issue erstellt, über den Webhook von GitLab und GLab bekommt der Dev-Assist mit das dieses erstellt wurde. Enthält das Ticket @dev-assist weiß dieser das er auf das Ticket reagieren soll. Im optimal Fall sind jetzt schon genug Informationen dabei um das Ticket in eine geregelte Struktur zu bringen mit denen ein Entwickler ganz genau weiß was er machen soll. In diesem Fall Antwortest du als Kommentar unter das Ticket, mit einem Vorschlag wie das Ticket aussehen wird. Antwortet dann der User mit @dev-assist publish wird die Konversation in den Kommentaren gelöscht die mit @dev-assist etwas zu tuen hatte und das ticket wird verändert wie du es vorgeschlagen hast. Sollten nicht genug Infos da sein um ein richtiges Ticket für einen Entwickler zu erstellen soll der Dev-assist in den Kommentaren nach fragen, bis er alle Infos hat und dann einen Vorschlag in den Kommentaren posten, ist dann der user zufrieden und postet @dev-assist publish soll es wieder wie im optimal fall ablaufen.

Techstack: Das Projekt ist ein reines API Projekt. Es wird keine GUI benötigt, da alles über GitLab läuft. Außerdem soll das SDK von opencode.ai verwendet werden. Das meiste sollte über agents und skills geregelt werden. Das Projekt ist in Typescript geschrieben. Alle Secrets werden in einer .env gespeichert. Aktuell wird ein Modell von Grok verwendet, in Zukunft könnte aber auch eins von OpenAI verwendet werden. Es wird in den meisten Fällen nur ein GITLAB_WEBHOOK_SIGNING_SECRET Token geben und manchmnal gar kein Token von GitLab weil die Authentifizierung und so weiter über Glab läuft.

Aufbau der Tickets vom Dev-Assist: Die erstellten Tickets vom Dev-Assist sollten immer den selben Aufbau mit dem Entwickler gut arbeiten kann. Dafür sollte die KI im Prompt einen teil haben der ganz genau beschreibt wie das Json aussehen sollte. Vielleicht könntest du dir auch anschauen wie GitLab vorschlägt wie man ein gutes Ticket aufbauen sollte.
